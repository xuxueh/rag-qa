# 评测报告 v3：100 条核验测试集 · 三种检索方案对比

> 数据来源：本仓库 `eval_v3.py`（一次完整运行，2026-10-17 20:38 开始）
> 原始结果：`eval_results_v3.json`（含每条失败案例的候选明细）
> 测试集：`eval_set_v3.json`（100 条，经 `verify_eval_set.py` 机器校验）

---

## 1. 实验设置

| 项 | 值 |
|---|---|
| 知识库 | 12 份公司制度文档 → 清洗切块后 **47 个 chunk** |
| 切块 | `chunk_size=200`、`overlap=20`、按中文句子边界递归切分 |
| 向量模型 | GTE 中文 small（`iic/nlp_gte_sentence-embedding_chinese-small`，本地） |
| 关键词检索 | BM25Okapi + jieba 分词 |
| 融合 | RRF，`k=60`，向量与 BM25 **各取 Top-10** 后融合 |
| 精排 | `BAAI/bge-reranker-v2-m3`（本地 cross-encoder） |
| 召回池 | Top-10（三种方案统一，保证可比） |
| 运行环境 | Windows / CPU-only / Python 3.13.2；无 GPU 加速 |
| 参评问题 | 有答案 90 条 + 无答案 10 条 = **100 条** |

三个方案（唯一变量是"排序方式"）：

- **A 纯向量**：Chroma 语义检索 Top-10
- **B 混合检索**：向量 Top-10 + BM25 Top-10 → RRF 融合 Top-10
- **C 混合 + Reranker**：B 的 10 条候选 → bge-reranker 重排（**不截断**，仍取 10 条）

> 为什么不截断：截断成 Top-3 会让 R@5/R@10 恒为 0，无法观察"rerank 会不会把正确项挤出前 K"。

## 2. 测试集构成

| 类型 | 条数 | 考什么 | 例子 |
|---|---|---|---|
| 普通事实查询 | 25 | 单条款事实抽取 | 婚假有几天？ |
| 条款编号查询 | 15 | 能否定位到具体"第X条" | 密码 90 天更换是第几条？ |
| 数字金额时间查询 | 20 | 金额/天数/比例/时限 | 单笔超过 5000 元谁审批？ |
| 相似条款辨析 | 15 | 多文档近似条款区分 | 出差餐饮补贴 vs 不出差餐饮补贴 |
| 跨文档查询 | 15 | 一条问题需要 2 份以上文档 | 被客户投诉后绩效系数最高多少？ |
| 无答案问题 | 10 | 知识库里确实没有（考拒答） | 公司年会在什么时候办？ |

**核验方式**（不是"看着像就写"）：每条都有 `source`（文件名）+ `articles`（条款号）+
`evidence`（原文逐字摘录）。`verify_eval_set.py` 会校验：
条款号确实存在于该文件、evidence 能逐字命中原文（多段用 `…` 连接）。本轮 100 条全部通过。

## 3. 主结果

### 3.1 文件级 Recall@K / MRR（n=90）

| 方案 | Recall@1 | Recall@3 | Recall@5 | Recall@10 | MRR | 平均耗时 | p95 耗时 |
|---|---|---|---|---|---|---|---|
| A 纯向量 | 71.1% | 88.9% | 93.3% | 96.7% | 0.810 | 25.7 ms | 35.4 ms |
| B 混合检索（RRF） | 87.8% | 97.8% | 98.9% | **100.0%** | 0.929 | 25.4 ms | 33.9 ms |
| C 混合 + Reranker | **97.8%** | **100.0%** | **100.0%** | 100.0% | **0.989** | 6111 ms | 7010 ms |

### 3.2 条款级 Recall@K / MRR（文件名 **且** 条款号都对，n=90）

| 方案 | Recall@1 | Recall@3 | Recall@5 | Recall@10 | MRR |
|---|---|---|---|---|---|
| A 纯向量 | 52.2% | 74.4% | 83.3% | 92.2% | 0.658 |
| B 混合检索（RRF） | 73.3% | 92.2% | 97.8% | 100.0% | 0.835 |
| C 混合 + Reranker | **94.4%** | **98.9%** | 98.9% | 100.0% | **0.967** |

### 3.3 跨文档题：所有期望文档是否都在 Top-10（n=21，含 also 文档）

| 方案 | AllSource@10 |
|---|---|
| A 纯向量 | 81.0% |
| B 混合检索 | **100.0%** |
| C 混合 + Reranker | **100.0%** |

## 4. 结论（每条都对应上面的数字）

**① 混合检索的收益是"真"的，而且不吃延迟。**
条款级 R@1 从 52.2% → 73.3%（**+21.1pp**），MRR 0.658 → 0.835；延迟不变（25.7 → 25.4 ms）。
原因：制度问题里"数字/编号/专有词"占比高（数字金额时间类 20 条、条款编号类 15 条），
纯向量对字面信号不敏感，BM25 正好补上。

**② rerank 的收益更大，但代价是 240 倍延迟。**
条款级 R@1 73.3% → 94.4%（**+21.1pp**），MRR 0.835 → 0.967；单次检索从 25 ms 涨到 **6.1 s**（CPU）。
CPU 上 10 个候选对逐对打分是主要成本。要不要付这个代价取决于场景：内部制度问答追求"别引错条款"，
值得；高并发在线问答则需要优化（见规划）。

**③ rerank 提升的是"排序"，不是"召回"——数据完全符合这个预期。**
A→B 把 R@10 从 96.7% 提到 100%（召回变强）；B→C 的 R@10 **保持 100% 不变**，
但 R@1 从 87.8% 提到 97.8%（排序变准）。这也说明：**召回池决定了系统上限**，
reranker 无法把不在候选里的正确块变出来。

**④ 文件级和条款级的差距，暴露了"知道是哪份制度、但答不对第几条"的问题。**
B：文件级 R@1 87.8% 但条款级只有 73.3%（**14.5pp 差距**）；C：97.8% vs 94.4%（3.4pp）。
说明 RRF 之后"找对文件"基本解决，剩下的是条款粒度定位——chunk 边界、以及同一文件里
多条相似条款（如"餐饮补贴"在 05/06 两份制度各写一遍）。

**⑤ 相似条款辨析是最难的一类，rerank 在这里价值最大。**
条款级 R@1：A 33.3% → B 46.7% → C **100%**。跨文档/近似条款这类"字面几乎一样、答案不一样"的问题，
向量和 BM25 都会混淆，只有 cross-encoder 读得懂"出差 vs 不出差"的差别。

**⑥ rerank 也有掉链子的地方（诚实记录）。**
跨文档类文件级 R@1 从 B 的 100% 掉到 C 的 93.3%：`X07「上班时间打游戏违反了哪条规定」`
在 B 里第 1 位命中 `12-员工行为规范`，rerank 后掉到第 2 位（第 1 位变成考勤制度的"代打卡"条款）。
原因：rerank 打分是"问题-单块"匹配，`12` 的那一块同时写了"例会制度"等无关内容，被稀释。
**工程上要防这种情况**：进 prompt 用 Top-3（而不是 Top-1），并对多文档问题保留全部期望文档。

## 5. 无答案题：能不能用精排分数当"拒答闸门"

方法：取 C 方案候选池里最高的 rerank 分数，低于阈值就判"知识库没有"。

| 组 | 最低分 | 中位数 | 最高分 |
|---|---|---|---|
| 有答案的 90 条 | 0.223 | 0.963 | 0.998 |
| 无答案的 10 条 | 0.001 | 0.046 | **0.944** |

- 最佳阈值 **0.21**：整体准确率 **99.0%**，无答案题拒答率 **90.0%**，有答案题答出率 **100.0%**。
- 唯一误判：`Y05「国际出差的差旅费报销标准是多少？」`（0.944）——知识库只写了国内差旅标准，
  但"差旅费报销标准"这个说法与 02 制度第五条高度重合，模型认为相关。
  这类"问题里的限定词（国际）不在知识库"是最典型的边界失败。
- 另一条接近阈值：`Y09「年终奖怎么算？」`（0.209）——知识库只有"月度绩效奖金"，属于"相似但不同"。

**结论**：分数阈值可以当第一道闸门（本测试集上 90% 拦截 + 0 误杀），但**不能替代 prompt 约束**，
因为边界案例（限定词不匹配、相似但不相同的概念）分数会很高。两层一起用才安全。

## 7. 局限（这些结论不能外推到什么场景）

1. **语料太小**：47 个 chunk，Top-10 已覆盖 21% 语料，R@10 指标接近饱和，
   rerank 的"排序收益"在小语料上被放大。真实企业上千文档时，各项绝对值都会下降。
2. **单次运行，无方差估计**：没有做多次重复/显著性检验；结论看的是同一次构建内的相对差异。
3. **rerank 分数不是校准概率**：0.21 这个阈值只在本知识库、本模型上验证过，换语料必须重标。
4. **只评了检索，没评生成**：本轮结论是"检索层"的。生成层（幻觉、引用正确率）需要调大模型，
   历史 50 条集上做过 LLM-as-judge（20/20 正确、Ragas context_precision 1.000），见 README。
5. **测试集由开发者自建**：存在"我出的题我做对"的偏差；缓解手段是逐条原文核验 + 6 类覆盖，
   但仍有偏。后续应加入来自真实提问日志的问题。
6. **CPU 环境**：6.1 s 的精排延迟不代表 GPU/生产环境；不要拿它当线上性能结论。
